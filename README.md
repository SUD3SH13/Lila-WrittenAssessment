# Setup

## Prerequisites

Make sure the following are installed:

- Node.js
- npm

Python 3.x is only required if you want to regenerate the processed data.

## 1. Clone the repository

```bash
git clone https://github.com/SUD3SH13/Lila-WrittenAssessment.git
cd Lila-WrittenAssessment
```

## 2. Install frontend dependencies

### Navigate to the React application

```bash
cd LILA-frontend
```

### Install dependencies

```bash
npm install
```

## 3. Start the development server

Run:

```bash
npm run dev
```

Vite will start the development server and provide a local URL, usually:

http://localhost:5173/

Open the URL in a browser.

## 4. Data Processing Setup

Python is only required if the processed data needs to be regenerated.

Install the required Python packages:

```bash
pip install pandas pyarrow
```

The preprocessing scripts convert the raw Parquet telemetry into:

```text
matches.json
heatmaps.json
```

These files are then consumed by the React application.


# Tech Stack

## Frontend

### React
Used to build the interactive visualization interface using reusable components.

React manages the application state for:

- Selected map
- Selected date
- Selected match
- Match playback
- Heatmap type
- Heatmap color mode
- Map zoom and pan

### Vite
Used as the frontend build tool and development server.

Vite provides:

- Fast local development
- Hot module replacement
- Production builds
- Static asset handling

### Mantine
Used as the primary UI component library.

Mantine is used for:

- `Paper`
- `Grid`
- `Stack`
- `Group`
- `Button`
- `ActionIcon`
- `Tooltip`
- `Text`
- Date selection
- Responsive layout

Using Mantine keeps the application's UI consistent while reducing the amount of custom CSS required.

### Day.js
Used for date handling and formatting, particularly for the date selection and match filtering functionality.

## Data Processing

### Python
Used for preprocessing the raw LILA BLACK telemetry before it is consumed by the frontend.

The preprocessing pipeline handles:

- Reading the raw telemetry files
- Identifying maps and dates
- Grouping records by match
- Identifying human and bot players
- Sorting events by timestamp
- Calculating match-relative time
- Converting world coordinates to minimap coordinates
- Aggregating telemetry for heatmaps

### Pandas
Used for manipulating, filtering, grouping, and aggregating the telemetry data during preprocessing.

It is particularly useful for transforming the raw event records into match-level and heatmap-level datasets.

### PyArrow
Used to read the raw Parquet telemetry files.

PyArrow allows the preprocessing pipeline to efficiently load the Parquet data before it is processed with Pandas.

## Visualization

### HTML Canvas
Used to render the heatmap overlay on top of the minimap.

The Canvas API is used to:

- Divide the map into a grid
- Place heatmap values into grid cells
- Calculate cell intensity
- Render radial gradients
- Overlay the heatmap without modifying the original minimap image

This allows the heatmap to be rendered dynamically when the user switches between traffic, kills, deaths, and loot.

### Minimap Images
The provided 1024×1024 minimap images are used as the spatial reference for the player movement and heatmap visualizations.

The minimap images are overlaid with:

- Player paths
- Player and bot positions
- Event markers
- Heatmap data

---

## Data Formats

### Parquet
The original telemetry is provided as Parquet files.

Parquet provides a compact, columnar format suitable for storing the large amount of telemetry generated by the matches.

### JSON
The processed telemetry is exported as JSON for consumption by the React application.

The frontend uses:

```text
public/data/matches.json
public/data/heatmaps.json
```

This avoids processing the original Parquet files in the browser.
